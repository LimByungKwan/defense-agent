### 원본 커밋에서 새 폴더를 만드는 절차

아래는 이번 재현에 사용한 저장소·브랜치·커밋을 기록한 절차입니다. `<새 폴더 경로>`는 프로젝트 폴더 밖의 새 빈 폴더(영문 경로)를 뜻합니다. 원래 작업 폴더를 대상으로 하지 않습니다.

```powershell
git clone --branch master https://github.com/LimByungKwan/defense-agent.git "<새 폴더 경로>"
git -C "<새 폴더 경로>" checkout --detach 52a048bf0d0ee10130c60c7966c2aabd0b719a1a
git -C "<새 폴더 경로>" rev-parse HEAD
git -C "<새 폴더 경로>" status --short
```

이번 확인에서 새 폴더의 `rev-parse HEAD`는 재현 대상 커밋과 일치했고 working tree는 clean이었습니다. 제출 커밋은 재현 대상 커밋 위에 이 문서만 추가한 커밋으로 기록합니다. 커밋 간 차이는 `git diff --stat 52a048bf0d0ee10130c60c7966c2aabd0b719a1a <제출 커밋>`으로 대조하며, 결과에는 `on-client/docs/STAGE_22_REPRODUCTION_RECORD.md` 한 파일만 나와야 합니다. 이 문서가 포함된 제출 커밋의 자기 해시는 적지 않습니다. 비공개 원문 제출 도구의 구체 명령은 과제 화면의 **「비공개 저장소 원문 준비 방법」**을 따릅니다.

## 데이터 보존·복원 계획과 한계

- 학생 데이터의 범위는 Git에 커밋된 `on-client/student/` 및 `on-client/docs/` 파일입니다. 백업은 GitHub 원격 저장소(`origin`, `master`)를 사용합니다. 커밋하지 않은 작업은 백업되지 않습니다.
- 복원은 새 빈 폴더에 `git clone`한 뒤 `git checkout --detach <커밋>`으로 수행합니다. 2026-11-11 실제로 수행했고, 새 폴더의 `HEAD`가 `52a048bf0d0ee10130c60c7966c2aabd0b719a1a`와 일치하는 것을 확인했습니다.
- `public/` 및 `student/`에서 `localStorage`·`sessionStorage`·`indexedDB` 검색 결과는 없었습니다. 이는 코드 검색 기준이며 실행 중 저장 동작을 확인한 결과는 아닙니다.
- 계정 연결 정보는 저장소 밖 Windows 사용자 프로필 아래에 보관됩니다(`tools/start-alekov.ps1`, `tools/app-credentials.ps1`). 이는 Git 백업 대상이 아니므로 복사하지 않았습니다. 새 PC에서는 앱의 `계정 연결 시작`부터 다시 진행합니다. 이번 재현은 같은 PC·같은 Windows 사용자 계정에서 이뤄져 해당 보관소 설정이 재사용됐을 수 있습니다.
- `.env.example`은 비밀값이 없는 설정 예시입니다: `ON_PORT=5189`, `ON_ENGINE_ADAPTER=./student/engine-adapter.mjs`, `ON_AI_MODEL=aleph/auto`, `ON_PROJECT_DIRECTORY`는 비어 있음, `ON_APPROVED_PUBLIC_PACKAGES=[]`. 새 폴더에는 `.env`가 없었고 기본 실행을 확인했습니다.
- 실제 외부 시스템(SDP/XDR) 데이터의 백업·복원은 시험하지 않았습니다. 수료 패키지 내보내기 도구(`tools/export-student-package.mjs`)는 사용하지 않았습니다. 앱의 기본 실행 확인은 실제 외부 시스템 데이터의 복원 확인이 아닙니다.
- 재현 중 문제를 고쳐 새 커밋을 만들면, 서로 다른 커밋의 결과를 합쳐 한 버전의 전체 성공으로 표시하지 않습니다. 수정한 최종 커밋에서 확인한 결과만 그 버전에 연결하고, 미확인 사항을 남깁니다.

## 버전·지원 범위·미완료 사항

| 항목 | 현재 기록 기준 |
|---|---|
| 프로젝트 버전 | 시작 틀 `0.2.21` 기반 학생 구현 |
| Node.js 버전 계약·관찰 | `package.json` 기준 `24.19.0`; 이번 실행은 `v24.22.1`, 시작 스크립트 허용 범위 22~24 안 |
| 기본 연결 동작 | 기본 학생 어댑터는 `disconnected`; `demo`는 예제 자료이며 실제 연결 성취가 아님 |
| 실제 SDP/XDR·AI 연결 | 연결 결과 미확인. 직접 연결을 확인하기 전 성공으로 기록하지 않음 |
| 실제 보안 조치 집행 | 미완료이며 실집행 연결은 아직 준비되지 않음 |
| 버전 상태 | 실제 연결·실집행 미완료라 `검증 중인 버전` |
| 새 환경 재현 상태 | 같은 PC·같은 Windows 사용자 계정에서 21단계 커밋을 재현. 새 PC·새 계정 재현은 아님 |
| 22단계 수료의 의미 | 원문 검토 기준 수료이며 운영 인증이나 `v1.0` 자동 인증이 아님 |

22단계 원문 검토 통과는 안내된 기준의 수료이며 실제 운영 인증이나 자동 `v1.0` 인증이 아닙니다. 원문 전달 완료와 AI 검토 통과도 서로 다른 상태입니다. 제출 저장소 주소·브랜치·커밋·단계는 ALEPH 화면에서 다시 대조하며, 비공개 원문 준비·전달 절차는 해당 과제 화면의 안내를 따릅니다.

## 이번 문서 수정에서 확인한 범위

AI는 명령을 실행하지 않았고, 아래 결과는 학생이 직접 실행·관찰한 학생 진술입니다.

- 학생 진술로 기록한 범위: 저장소·브랜치·재현 대상 커밋, 원래 폴더 상태, 별도 폴더 clone 및 checkout, 런타임·검사·시작·브라우저·종료·재실행, Demo 표시, 데이터 보존·복원 관련 코드 검색 결과.
- 미확인: 제출 커밋의 40자리 해시와 두 커밋 간 diff 결과, 새 PC·새 계정 재현, 실제 SDP/XDR·AI 연결, AI 설명, 접속 판정, 패키지 조회, 실제 보안 조치 집행.
- 22단계 문서가 포함된 제출 커밋의 자기 해시는 적지 않습니다.
